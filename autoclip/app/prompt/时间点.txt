## 核心原则：精准、完整、自然

1.  **精准定位**：时间戳必须严格对应话题相关的讨论内容。
2.  **完整性**：时间范围必须完整覆盖一个话题的所有核心讨论点，确保语义完整。
3.  **自然边界**：优先在自然停顿、语气转换或语义边界处定位时间点，避免硬切。

## 关键指令：如何确定 `start_time` 和 `end_time`

### `start_time` 的确定：
-   应定位到讨论该话题的**第一句核心发言**的开始时间。
-   忽略该发言之前的无关寒暄、口头禅或过渡语。
-   **优先选择**：在语义边界处开始，确保话题引入自然。

### `end_time` 的确定 (最重要)：
-   **必须**是覆盖该话题核心讨论的**最后一句话的结束时间戳**。
-   **语义完整性**：确保话题讨论在语义上完整，不出现突兀的断点。
-   **自然结束**：优先选择在自然停顿、总结性语句或话题转换处结束。
-   **断点优先**：`end_time` 必须落在**一句话讲完、下一句还没开始**的自然停顿间隙（静音处），**绝对禁止**在句子中间或观点展开过程中硬切。宁可片段略短，也不要在语气未收住处截断。
-   **禁止拖尾**：高光剧情爆发并收尾后，如果后面是反应/过渡/废话/无关镜头，**不能为了凑时长把尾巴硬收进来**。`end_time` 应贴着高光收尾后的第一个自然停顿处截止。
-   如果话题结束后，有几句总结性、过渡性或无关的句子，**绝对不能**将它们包含进来。`end_time` 必须在这些句子开始之前就结束。
-   如果话题的讨论一直持续到所提供SRT文本块的末尾，那么 `end_time` 就应该是最后一句相关字幕的结束时间戳。
-   **错误做法**：将 `end_time` 无脑设置为整个文本块的结束时间。这是绝对要避免的。

### 时长控制原则（严格执行）：
-   **硬性最小时长**：每个片段至少 30 秒，低于此时长说明高光信号不足，应与相邻片段合并
-   **目标时长**：悬念断点片 30-60 秒；完整高光段 60-90 秒（视频号信息流最佳实践）
-   **最大时长**：单个片段不超过 120 秒，过长的应拆出多个独立高光点
-   **合并策略**：仅当相邻两个片段都不足 30 秒且语义相关时，才合并为一个片段
-   **断点优先于凑时长**：高光本身不足 30 秒时，**优先在爆点后的自然停顿处结束**（哪怕略短于 30 秒），而不是无脑向后硬凑时长拉进无关内容。合并两个相邻高光通常比硬拖一条尾巴更好。
-   **质量优先**：宁可片段稍长但内容完整，也不要为了追求数量而产生内容不完整的短片段；更**不要为了凑满时长而牺牲结尾质量**。

## 时长验证与合并流程

**在确定每个话题的时间区间后，必须执行以下验证步骤：**

1. **时长计算**：计算每个话题的实际时长（end_time - start_time）
2. **最小时长检查**：如果任何片段时长少于 30 秒，说明高光信号不足，标记为需要合并
3. **合并判断**：检查相邻片段是否可以合并：
   - 两个片段都不足 30 秒
   - 片段内容语义相关或逻辑连贯
   - 合并后总时长不超过 120 秒
4. **执行合并**：将符合条件的相邻片段合并，更新 outline 和 content 字段
5. **最终验证**：确保所有输出片段时长落在 30-120 秒区间

**重要提醒：悬念断点片允许 30-60 秒（断在钩子上引流看全集）；完整高光段 60-90 秒。
只有低于 30 秒才需合并——不要为了凑时长把完整的高光事件无脑拉长，那会毁掉钩子。**

**结尾质量校验（输出前必须自检）**：
1. `end_time` 是否落在自然停顿/句子间隙处？是否避免在句子中间硬切？
2. 高光剧情结束后是否还拖了几秒反应/过渡/无关镜头？若有，应把 `end_time` 提前到爆点收尾后的第一个停顿处。
3. 是否有"为了凑满 30 秒把尾巴硬收进来"的情况？若有，优先用"合并相邻高光"或"在自然停顿处提前截止"解决，而不是无脑向后扩展。

## 输入格式
你将收到一个JSON对象，包含：
-   `outline`: 一个包含**多个**待处理话题的JSON数组。
-   `srt_text`: 与这批话题相关的**单个**SRT文本块，格式为 `序号\n开始 --> 结束\n文本\n\n`。

## 输出格式
你必须输出一个JSON数组，每个元素包含：
-   `id`: 话题在原始outline中的ID（如果是合并话题，使用第一个话题的ID）
-   `start_time`: 格式为 `HH:MM:SS,mmm`
-   `end_time`: 格式为 `HH:MM:SS,mmm`
-   `outline`: 话题的原始大纲内容（如果是合并话题，合并所有相关大纲）
-   `content`: 从SRT中提取的对应文本内容

**严格要求**：
-   只输出JSON，不要任何其他文字
-   确保JSON格式正确，可以被解析
-   时间格式必须与SRT保持一致
-   **最终验证**：输出前必须验证每个片段的时长（end_time - start_time）落在 30-120 秒区间
-   **禁止输出**：任何时长少于 30 秒的片段（高光信号不足），必须通过**合并相邻高光**解决；确需扩展时也**只能在自然停顿处截止**，**禁止**为了凑时长把高光之后的反应/过渡/无关镜头无脑收进来。

**严格的JSON输出要求：**
1. 输出必须以 `[` 开始，以 `]` 结束，不要添加任何解释文字、标题或Markdown代码块标记
2. 使用标准英文双引号 "，绝不使用中文引号 "" 或单引号
3. 确保所有括号、方括号正确匹配，对象间用逗号分隔，最后一个对象后不加逗号
4. 字符串中的引号必须转义为 \"
5. 不能包含任何注释、额外文本或控制字符
6. 确保JSON格式完全有效，可以被标准JSON解析器解析

**输出示例格式：**
```
[
  {
    "outline": "话题标题",
    "content": ["要点1", "要点2"],
    "start_time": "00:01:23,456",
    "end_time": "00:02:34,567"
  }
]
```

## 语义边界识别指南

### 自然开始点特征：
- 话题引入性语句（"说到..."、"关于..."、"我们来聊聊..."）
- 观点转折（"但是..."、"不过..."、"另一方面..."）
- 新的讨论对象或案例引入
- 语气或语调的明显变化

### 自然结束点特征：
- 总结性语句（"总的来说..."、"总结一下..."、"这就是..."）
- 话题转换信号（"接下来..."、"另外..."、"换个话题..."）
- 观点收尾（"所以..."、"因此..."、"这就是我的看法"）
- 自然停顿或语气放松

### 避免的切割点：
- 句子中间
- 观点展开过程中
- 逻辑推理的关键环节
- 没有明显语义边界的连续讨论

## 示例与思考过程

### 输入:
```json
{
  "outline": [
    {
      "title": "投资理念与心态管理",
      "subtopics": ["长期投资vs短期投机的选择逻辑", "市场波动时的心理调适方法"],
      "chunk_index": 3
    },
    {
      "title": "职场技能提升策略",
      "subtopics": ["跨行业技能迁移的实践经验", "副业发展的时机选择"],
      "chunk_index": 3
    }
  ],
  "srt_text": "...\n551\n01:15:32,800 --> 01:15:35,200\n这种儿媳妇我们家可要不起\n\n552\n01:15:35,500 --> 01:15:38,900\n妈我嫁的是你儿子不是你们全家\n\n553\n01:15:39,200 --> 01:15:42,100\n你算什么东西也敢跟我这么说话\n\n554\n01:15:42,300 --> 01:15:47,800\n三年了我伺候你们一家老小换来一句要不起\n\n555\n01:15:48,100 --> 01:15:53,500\n那份房产证上写的是我的名字你们住的是我的房子\n\n556\n01:15:53,800 --> 01:15:58,200\n什么你说什么房产证\n\n557\n01:15:58,500 --> 01:16:03,900\n还有一件事你们一直想知道我爸是谁对吧\n\n558\n01:16:04,100 --> 01:16:07,200\n明天他就到了\n..."
}
```

### 思考过程:
1.  **处理第一个话题**: "婆媳当众撕破脸"。
    *   **定位起点**: 冲突从 `551` 婆婆的挑衅「要不起」直接开场，无需铺垫，是天然的钩子。`start_time` 是 `01:15:32,800`。
    *   **定位终点**: 情绪在 `555` 亮出房产证时完成一次完整释放（建立冲突→爆发→反转打脸），观众有完整爽感。**结尾自然断点**：`555` 说完"你们住的是我的房子"后是 `556` 婆婆震惊反应"什么你说什么房产证"，两句之间无句子中间硬切风险，`end_time` 可停在 `555` 结束的 `01:15:53,500`（自然停顿处）。
    *   **时长验证**: 01:15:53,500 - 01:15:32,800 = 20.7 秒，不足 30 秒最小要求。**优先考虑相邻高光合并**，而不是向后硬拖。
2.  **处理第二个话题**: "神秘父亲即将登场"。
    *   `557`-`558` 是身份揭露的悬念抛出，但仅 9.1 秒，远不足 30 秒，且与上一段语义高度连贯（同一场冲突的延续）。
3.  **合并决策**: 第二段独立成片时长不够且钩子依赖前文，与第一段合并。
4.  **执行合并**: 合并区间 `01:15:32,800` → `01:16:07,200`，总时长 **34.4 秒**，落在 30-60 秒区间。合并后 `end_time` 落在 `558` "明天他就到了" 这句话讲完处，是自然断点，非硬切。
5.  **切点判断**: 结尾停在「明天他就到了」——身份未揭晓、悬念拉满，属于典型 `suspense_cut` 断点，引导观众点进去看全集。**不要**再往后延到父亲登场，那会把钩子消耗掉。
6.  **结尾质量自检**: `end_time` 落在句子讲完的自然停顿处，未拖尾、未硬切。⚠️ 反例提醒：如果高光在 `555` 就收尾且后续是无关反应/过渡镜头，**绝不能为了凑 30 秒把 `556/557` 硬拉进来**；此时应让片段停在 `555` 的自然停顿处（哪怕略短于 30 秒），或与更早的高光合并。
