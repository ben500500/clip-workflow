# hook_id.py 取号脚本——实现需求（2026-11-08）

## 一句话

写一个跑在 163 服务器上的取号脚本，后端 `POST /assets/hook-codes/take` 代理调用它，
前端开单弹窗点「代取 N 个号」直接回填——投放专员不用再 SSH 上服务器手工跑。

## 系统已有的（不用做）

后端代理口已上线（`POST /assets/hook-codes/take?count=N`）：
- 读 `ASSET_HOOK_ID_CMD` 环境变量（.env 里配置），拼上数量参数后 `subprocess` 执行；
- stdout 按行解析五位编号（`[0-9A-Z]{5}`），数量不够或退出码非 0 → 502 报错；
- 未配置 `ASSET_HOOK_ID_CMD` → 501（前端提示走手工粘贴旁路）；
- 代取的号进入投产口后走既有**硬查重＋白名单校验**（一钩一号发了即烧的铁律不变）。

所以你只需要实现 hook_id.py 本身＋在 .env 里配一行。

## hook_id.py 需求

### 输入

```bash
python3 /home/cc12703/hook_id.py <count>
```

- `<count>`：要取几个号（1~50，整数）。

### 输出（stdout，严格格式）

```
7C0M1
7C0M2
7C0M3
```

- **每行一个五位编号**，无前缀无后缀无空行——后端按行正则 `[0-9A-Z]{5}` 提取；
- 五位编号格式：日期 2 位（base36）＋剧码 2 位＋当日序号 1 位（与现行 hook_id.py 一致）；
- 编号必须全局唯一（多人共用防撞码——用 NAS 共享盘的占用清单文件加文件锁）。

### 副作用

- 取出的号**立刻写入占用清单**（NAS 共享盘的 JSON/文本文件），哪怕前端取消开单号也不回收——
  "一发即烧"是现行铁律，作废的单不复用；
- 占用清单需加文件锁（`fcntl.flock` 或等价），防多人同时取号撞号。

### 错误处理

- 可用号不够 → 打印错误到 **stderr**、退出码非 0（后端会把 stderr 拼进 502 报错）；
- 不许在 stdout 里输出除编号以外的任何内容（日志走 stderr）。

### 安全

- 脚本只读共享盘的占用清单＋原子写入新占用的号——不碰素材库数据库、不碰 MinIO；
- 权限：cc12703 用户可执行即可。

## 部署步骤（做好后一行配上去）

```bash
# 1. 脚本放到 163 固定路径
scp hook_id.py cc12703@192.168.1.163:/home/cc12703/hook_id.py

# 2. 验证手动跑一次
ssh cc12703@192.168.1.163 "python3 /home/cc12703/hook_id.py 3"

# 3. .env 里加一行
echo 'ASSET_HOOK_ID_CMD=python3 /home/cc12703/hook_id.py' >> /home/cc12703/clip-workflow/.env

# 4. 重启 backend（env 变了必须重建）
cd /home/cc12703/clip-workflow && docker compose up -d --force-recreate backend
```

配置好后前端开单弹窗的「代取 N 个号」按钮就亮了（此前点了提示走手工粘贴）。
