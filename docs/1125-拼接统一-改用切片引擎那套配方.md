# 拼接统一 · 素材库改用切片引擎那套现成代码（2026-11-25）

## 0. 原话（逐字照抄，任何 Agent 禁改写）

> 「拼接你可不可以直接用短剧切片的那套现成的代码？就是那边我更新了，你这边也无需再动。」

批准动手的话：「好的」。

这份文档了结的是 11-24 挂着的债：上一轮用户说「我要的那个拼接是最后一步，你可以先不做，到时候直接把短剧切片中的那个功能搬过来就可以了」（见 [1124-极简二轮](1124-极简二轮-导入并入我的口径与失败缺口.md) §6）。搬的不是界面，是**配方**。

## 1. 为什么此前那一份必须退掉

素材库这一侧此前自带一套 `filter_complex`（`asset_compose_service.build_concat_filter` / `build_concat_cmd`），与 `engines/slice.py::concat_segments` 做的是同一件事。两份写法已经在两个月里漂移过两次，而且漂移的方向都是**切片线修了、素材库没跟上**：

| 切片线的修复 | 日期 | 素材库这一侧的代价 |
|---|---|---|
| 同规格免重编码（concat demuxer 流拷贝＋拼完校验时长再回退） | 11-23 | 素材库每次拼都重编码一遍，豆包成片＋同参切片这种常见组合白掉一档画质、多花几十秒 |
| 子进程剔 `LC_*`／`LANG`，防中文 drawtext 出豆腐块 | 11-22 | 素材库拼出来的片子带中文字幕/贴片时可能直接变方块 |

更要紧的是第三处：`api/upload.py::_ffmpeg_concat` 的重编码回退档**硬编码 `scale=1920:1080`**。全链路是 9:16 竖屏（豆包成片恒 720×1280），谁在素材库线上调了它，产物就是「拼成功但竖屏片加左右黑边塞进横框」。所以 11-04 当时选择自己写一份，而不是复用它——**不复用是对的，多写一份是错的**，正解是收敛到引擎。

## 2. 改完之后配方在哪里

```
engines/slice.py
├── :987  _probe_concat_spec(path)        一次 ffprobe 取「有无音轨／时长／帧率」
├── :1030 build_concat_filtergraph(...)   纯函数：段规格 dict → (滤镜串, 补几条静音输入, 人话说明)
├── :1075 concat_segments(parts, out, threads=1, encoder, copy_if_possible, faststart=False)
└── :1249 _concat_demuxer(...)            同规格流拷贝快通道（拼完校验时长，不符回退重编码）
```

`backend/app/services/asset_compose_service.py` 退成**适配层**，只剩三道活：

| 职责 | 落点 | 为什么留在 backend 而不是塞进引擎 |
|---|---|---|
| 段数闸门 2～3 | `:88-89` `MIN/MAX_SEGMENTS`，`:372` 判 | 引擎对单段是 `shutil.move` **搬走输入**（切片线传临时件本该清）。素材库传的是下载缓存件／已入库产物，被搬走＝数据事故。**MIN_SEGMENTS=2 就是那道护栏，别下调到 1** |
| 「不是视频就别拼」＋缺 ffprobe 就说人话 | `:377-384` | 引擎不预探每段是不是视频；一线要看得懂是哪一段坏了 |
| 阻塞的 ffmpeg 放线程池／引擎异常翻成人话／产物空判失败 | `:385-398` | 素材库三个拼接口都挂在同一个 uvicorn 事件循环上；引擎只 raise，不说「拼接失败」这种交付话术 |

引擎侧这次是**只加不改**（用户要求「那边更新了这边不用动」，反过来说就是不能把切片线现有产物改了）：

1. **缺音轨兜底**：某段整片无声时旧写法裸引用 `[i:a]` 会让整条命令当场失败，改为补一条 `anullsrc` 并按该段时长 `atrim`（anullsrc 无限长，不剪住 concat 永不收尾）；
2. **混帧率归一**：只在各段帧率**真的不一致**时才加 `fps=`（同帧率加等于再做一次 CFR 重采样，会让切片线既有成功产物逐帧变样），目标帧率取首段，与几何同源；
3. **`faststart` 开关**：默认 `False`（切片线产物字节不变），素材库显式传 `True`（产物要挂网页边下边播）；
4. 把上面两条的配方从 `concat_segments` 体内**抽成纯函数** `build_concat_filtergraph`，单测直接喂 dict，不依赖真装 ffmpeg——本机 ffmpeg 连 `drawtext` 都没有，配方不抽出来就没法在本地验。

适配层传参口径（`asset_compose_service.py:337-353`）：`threads=0`（引擎默认 1 是给切片线限 CPU 的，素材库一次只拼一条且**同步等**，照默认会把几秒的活儿拉成几十秒）、`faststart=True`、`copy_if_possible=True`、`encoder="libx264"`。

## 3. 三条拼接线，一个汇流口

```
手工两段拼接  concat_two_videos  misc.py:12719 ─┐
回收后自动拼  _auto_concat_recovered misc.py:10890 ├─→ _concat_render (misc.py:12621)
组合导出矩阵  _run_compose_matrix  misc.py:13386 ─┘        │ 调用点 :11029 / :12769 / :13463
                                                          ↓
                                    compose.concat_segments → engines/slice.py::concat_segments
```

`_concat_render` 是**唯一**碰落桶与产物记账的地方（探首段定目标画幅 → MAX_SEGMENT_SECONDS 守卫 → 拼 → 抽帧/叠加 → 落 MinIO → 写 `asset_outputs`）。这条结构由守卫用例钉着：`misc.py` 里 `await _concat_render(` 必须恰好 3 处、`compose.concat_segments(` 必须恰好 1 处。

## 5. 分发模型 ——「那边更新这边不用动」在什么前提下成立

| 消费方 | engines 的进容器方式 | 改了 `engines/slice.py` 之后 |

| 唯一事实来源 | 仓库根 `engines/`；`slice-worker/engines/` 是 `.gitignore` 的构建副本 | 别往副本里改 |

## 7. 顺手查出来的一条既有红（切片线，非本批）
