# 多视频号素材去重（素材变体 1:N + 指纹校验闭环）设计方案（圆桌定稿）

> 版本：20260817 圆桌定稿 · 已落地 Phase 0/1/2
> 背景：一套视频切片完成后，需要做多次去重处理给多个视频号上传。现状 `slice.py` 的去重
> （crop/hflip/speed/color/vignette/jitter）只打掉平台查重的 L0-L2 层，打不掉 **L3 音频指纹**
> 和 **L4 时域序列**——这就是"同一素材发多个视频号必撞车"的根因。

---

## 一、平台重复素材判断标准（外派调研结论）

平台对视频查重是**多模态指纹叠加**，按层级：

| 层级 | 判断维度 | 现有系统覆盖 |
|------|---------|------------|
| L0 精确哈希 | MD5/SHA | ✅ 易规避 |
| L1 感知哈希 | pHash/dHash | ⚠️ 变形可打掉 |
| L2 视觉相似 | 关键帧/颜色直方图/ORB | ✅ slice.py 变形可部分规避 |
| **L3 音频指纹** | 音频声纹 | ❌ 盲区 |
| **L4 序列/时域** | 多帧时间序列匹配（同素材不同切法） | ❌ 盲区 |
| L5 语义级 | 帧 embedding（CLIP 类） | ⏸ 远期 |

**关键结论**：多版本必须引入**结构性差异**（切点漂移、拼接重排、音频替换），并建立**指纹校验闭环**。

---

## 二、圆桌会议收敛结论（5 角色 × 3 轮）

采用 **「素材变体 1:N + 指纹校验闭环 + pgvector 指纹库」** 路线，不推倒重来。

- 架构师：切片输出从 1:1 变 1:N，引入"素材变体"，不破坏现有 SliceOutput 单发链路。
- 视觉算法：必须建素材指纹库，覆盖 L3 音频 + L4 时域这两个盲区。
- 内容运营：N 版本要有结构性差异，否则平台 L4 序列一比对全命中。
- 风控：一个变体只绑一个账号、可审计；宁可降级不可原样发 N 号。
- 后端工程：落点明确 `ClipVariant` 表 + `fingerprint_service` + pgvector。

---

## 三、落地方案（融入现有工作流）

```
AI选点 → 区间检测 → 切片(基准版)
   → [已落地] 多版本生成(N 套结构性差异参数，复用 dedupe 引擎)
   → [已落地] 指纹入库 + 跨版本比对(phash+音频+时域)
   → [已落地] 撞车自动换参重试(N 次)
   → [已落地] 变体→账号绑定分配（一账号一变体硬约束）
   → 多运营者发布(现有 publish 链路)
   → [已落地] 发布后回写 content_hash + variant_id 审计（Publication.variant_id）
```

### Phase 0（数据层）✅ 已落地
- 新表 `clip_variants`（素材变体）：output_id / variant_group_id / variant_index /
  file_key / dedupe_config / structural_diff / status / phash_distance / audio_distance /
  collision / collision_reason / account_id（**一账号一变体唯一约束**）。
- 新表 `video_fingerprints`（视频指纹）：output_id / variant_id / algorithm(phash_v1|audio_v1|seq_v1) /
  hash_value / vector / duration / resolution。
- `slice_outputs` 加 `variant_group_id`（变体组聚合，未开多版本为 NULL，零侵入）。
- `slice_tasks` 加 `variant_count`（>1 时切片成功后自动派生 N 个去重版本）。
- `publications` 加 `variant_id`（发布回写变体，审计）。
- 启用 pgvector 扩展（不可用时回退字符串汉明距离）。

### Phase 1（工作流）✅ 已落地
- `fingerprint_service.py`：`compute_visual_fingerprint`（pHash 64bit，ffmpeg 抽帧 + numpy/cv2 DCT）、
  `compute_audio_fingerprint`（16k 单声道能量签名，覆盖 L3 盲区）、
  `compute_segment_fingerprint`（scene 检测场景切分签名，覆盖 L4 盲区）、
  `compare_fingerprints` / `is_collision`（多路距离 + 综合加权）。
- `variant_service.py`：`build_variant_recipes`（N 套结构性差异配方，随机组合
  crop/speed/saturation/noise/scanline/vignette/roll_band/jitter/sharpen/colorbalance/
  temperature/watermark）、`generate_variants_for_output`（复用 dedupe 引擎派生变体 →
  指纹入库 → 撞车自动换参重试 ≤N 次 → 落库 ClipVariant + VideoFingerprint）。
- celery 任务：`generate_variants_task` / `verify_variant_fingerprint_task`；
  `_save_slice_outputs` 在切片成功后按 `variant_count>1` 自动投递变体生成（异步不阻塞主链路）。
- 配置：前端去重模式新增"多版本数"（InputNumber，1~20），提交 `variant_count`。

### Phase 2（可观测）✅ 已落地
- `api/variants.py`：变体矩阵看板 `/variant-matrix`、变体详情、手动生成 `/variants/generate`、
  发布前指纹复核 `/variants/{id}/verify`、变体→账号绑定 `/variants/{id}/bind`、
  撞车阈值运营可调 `/variant-thresholds`（system_config.variant_thresholds）。

---

## 四、关键护栏

- `variant_count=1` 时完全等同现状（零侵入可回滚）。
- 多版本生成异步不阻塞主链路。
- 撞车失败宁可降级人工处理，**绝不把同一素材原样发多号**（一账号一变体硬约束）。

## 五、撞车判定阈值（可运营调整）

| 指纹 | 默认阈值 | 说明 |
|------|---------|------|
| phash（画面） | 0.20 | 画面 pHash 归一化距离，低于此判定高度相似 |
| audio（音频） | 0.15 | 音频声纹距离，覆盖 L3 盲区 |
| seg（时域） | 0.30 | 场景切分序列距离，覆盖 L4 盲区 |
| combined（综合） | 0.15 | 加权综合：0.5*phash + 0.3*audio + 0.2*seg |
