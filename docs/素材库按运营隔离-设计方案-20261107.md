# 素材库按运营隔离——设计方案（2026-11-07，待拍板）

用户口径：素材**前期导入大家可以一起做**；后期的挑选文案、生成豆包（投产/投板/成片）
结果**按账号（运营）区分**。本方案只做设计不动代码，三个拍板项见文末。

## 一、现状盘点（骨架都在，缺的是执行）

| 件 | 现状 |
|---|---|
| `User.data_scope`（own/all） | 字段已在、登录口默认按角色给值，**素材库读口从未执行它** |
| 归属锚点 | 全都在写：`AssetItem/AssetBatch.created_by`=导入人、`AssetSummary.reviewed_by`=过审人（过审写/撤审清）、`AssetProduction.created_by`=投产人 |
| 跨人闸门 | 已上线（11-06 拍板②）：替别人的批次扣费要确认——「人」的概念已进闸门 |
| 断的三层 | 审核台不分「谁的候选」、生产单/成片墙不分「谁的链路」、统计不分「我的/全站」 |

## 二、设计原则

1. **前期共享不动**：导入、反推、出文案（候选池）全站共享，谁都能做、都看得到。
2. **归属锚点＝过审那一刻**（`reviewed_by`）。审核就是"挑选"这个动作本身，挑了即认领；
   投产单挂在候选名下（`created_by`=投产人）、成片挂在单名下——隔离天然沿链继承，零迁移。
3. **一条候选一个主人**：pending 队列本来就是先到先得（抢先过审已有 R-6 报错）。
   同一素材两个运营都要 → 各自「重出文案」出一条自己的候选、各自过审，互不挤占。
4. **权限复用 `data_scope`**：operator（own）默认只见自己的链路、可切"全部"只读；
   admin（all）全量；material 无投产动作、维持只读全量。
5. **钱的事不隔离**：号池计数、审计、成本确认全站口径不变（只补一行「我的今天」分列）。

## 三、改动清单（四层）

### A. 数据层：零迁移
归属链已闭环：`reviewed_by`（候选）→ `production.created_by`（单）→ output 随单。
不需要新列。（P2 可选：`AssetBatch.claimed_by` 素材级认领，仅当拍板项 2 选"锁素材"才上。）

### B. 读口：加 owner 参数
- `GET /assets/summaries`：owner=me → pending 照旧全量（大家都能挑）＋**已过审区只显自己的**；
- `GET /assets/productions`：owner=me → `created_by=me`；owner=all 全量只读；
- `GET /assets/outputs/groups`：加 owner（join production.created_by 聚合）——成片墙「我的片子」一层；
- 统计行：我的／全站两行并排（号池仍全站口径）。

### C. 写口：闸门已有，补一致性
- 过审写 `reviewed_by`（已有）✔
- 投别人的过审候选：复用 `_cross_person_gate`（判定从 batch.created_by 换成 summary.reviewed_by），
  确认后 `production.created_by` 仍记实际投产人——谁投的账算谁的。
- 出文案口不动（共享池）。

### D. 前端：每页一个开关（精简原则）
- 审核台／生产单／成片墙：Segmented「我的｜全部」（operator 默认我的，admin 默认全部）；
- 归属人在卡片/行上以 12px 灰字显示，不新开列；
- 投板确认弹窗的统计行分「我的／本批」两行已有结构，加 owner 前缀即可。

## 四、拍板项（3 个）

1. **认领时点**：过审即归属（推荐——零新概念、零迁移） vs 显式「认领」按钮（多一步操作）。
2. **同素材多运营**：允许各自重出候选各自过审（推荐——候选表天然支持） vs 锁素材一人独占。
3. **material 角色的成片墙**：维持全量只读（推荐——成片墙是最终挑片屏） vs 也按人过滤。

## 五、不做

- **豆包账号级隔离**：投板走共享的企微任务板，豆包账号在企微/RPA 侧分派，
  素材库既看不到也切不了账号——失败粒度是"板上的任务行"，不是账号。
  账号级隔离要动 RPA 派单，属另一条线（rpa/），不在本设计内。
