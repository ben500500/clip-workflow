## 1. 产品口径（按专家建议拍板）

| 口径 | 决策 | 依据 |
|---|---|---|
| 钩子多样性 | 一期=后端按分片划分 hook_video_keys 子集（方案 A，Go/引擎零改动）；random 接受统计多样性；「每钩子硬覆盖」二期引擎扩展 `--hook-assignments` | 后端专家 §3.2：现有引擎表达不了硬覆盖约束 |
| 部分失败终态 | 父任务混合态（部分 completed 部分 failed）→ 父=completed＋保留全部成品＋progress_message 注明「N/M 分片失败」＋前端黄标；与 episode 状态机 has_completed+has_failed→completed 口径一致 | 后端专家 §4.2／架构 §三.1 |
| 并发闸门 | max_concurrent_tasks **按父任务计数**：闸门 SQL 只数 `parent_task_id IS NULL` 的 running/pending 行；分片行豁免 | 三方一致（k=3 任务独占默认上限 4 = 其他用户全 429） |

## 2. 一期范围（收窄后定稿）

- **做**：fast/dedupe 两模式、无钩子混拼、无 remotion、k≤3、源片体积 ≤1.5GB（超限自动回退整任务模式）；
  分片全走公共流竞争拉取（**保留 subtitle 专用流隔离**）；节点白名单=163 双容器+112（Mac 不参与）。
- **不做（显式排除）**：钩子 random 预选切块（该机制在引擎运行时，后端无可切之物——v1 失实表述删除）；
  加权调度（worker_nodes 无耗时字段，时间数据不可信——X66，一期用白名单静态份额）；work stealing；combine 链。
- **k 取值**：一期常数 **30 成品/分片**（后端专家建议：饱和成品数无实测，避免伪精确），验收中校准。

## 3. 数据模型（定稿）

`slice_tasks` 加两列（nullable，旧行为不变；**不建新表**——分片行必须在 slice_tasks 内，
worker 回调/上传/鉴权契约按 task_id 寻址零改动，SliceOutput 外键自然挂分片行）：

- `parent_task_id UUID NULL`（父行=NULL，历史行=NULL 天然兼容）
- `shard_index INTEGER NULL` / `shard_total INTEGER NULL`

迁移走本仓库惯例（**不跑 alembic upgrade**）：`database.py` compat 清单加两列 + 手工部分索引
`CREATE INDEX IF NOT EXISTS ix_slice_tasks_parent ON slice_tasks(parent_task_id) WHERE parent_task_id IS NOT NULL`；
alembic/versions 同步空 head 迁移保 stamp 一致；**不加 updated_at**（tasks.py:264 勿改注释）。

## 4. 核心机制（吸收后端 M2/M5/M7 + 架构 M2/M3 + SRE M1/M6）

### 4.1 切分器（run 端点内，generate_cutlist 之后）
- 层位：候选冻结/boundary_refine（整集一次性写）之后、建行之前切——「创建任务时切」唯一正确（后端 §1.1）。
- **切分单位=输出名 group**（同名多行=混剪组，不可跨片拆）；`build_clip_name` 全局唯一编号在整表阶段完成。
- 父行=聚合行（不派发），k 个分片行带完整 config 快照；父行 outputs_total=Σ分片（拆分时算好存行）。
- **hook_mix_output_count 按 group 占比缩放**（防 ×k 翻倍）；钩子子集按分片划分（口径表）。

### 4.2 父任务生命周期（三方补齐的最大空白）
- 状态机：pending →（首分片起跑）running →（全部分片终态）completed / failed / completed+partial标注。
- **推进者=分片回调事务内**：分片终态写入（现有幂等守卫）→ `SELECT ... FOR UPDATE` 父行 → 重算
  （纯函数：全 completed→completed；全 failed/cancelled→failed；混合→completed+partial 标注；否则 running 重算进度）→ 同事务 commit。
  **禁增量累加**（并发丢更新）、**禁独立聚合 Celery 任务**（滞后窗口破坏 finalize_slices 轮询）。
- episode 终态联动复用 `_refresh_episode_status`（父行参与判定不再双重计数——分片行排除出该函数的行集）。
- **sweep 语义（SRE M1）**：①父行豁免僵尸巡检（无 lease 必被误杀）；②分片行回收阈值独立收紧
  `max(3×预期分片时长, 45min)`（7h 主阈值对 30min 分片=漏杀）；③sweep 收尸分片→联动父行重算。
- **父任务 watchdog（架构 M5）**：beat 巡检扩展——父行 running 且存在非终态分片超过
  `max(预估墙钟×2, 2h)` → 自动补投缺失分片（公共流）＋告警（X14 分片丢消息的兜底，不依赖 7h sweep）。

### 4.3 取消/删除扇出（架构 M3）
- cancel 父任务：父行先幂等写 cancelled_at（分布式锁语义）→ 逐分片走现有 cancel 出口（终态守卫×4 天然防复活）
  → 父行重算。迟到分片回调被守卫 suppress，成品保留走 `_record_kept_outputs`。
- delete 父任务：逐分片 `remove_slice_task_from_streams` + 按**各分片前缀**清 MinIO（父删除清不到子前缀）。

### 4.4 重试（SRE M3 + 架构 M4）
- 分片行/父行的 retry 一律**父级语义**：只重跑非终态分片（已完成分片不动、成品不重复——终态 hash+file_key 去重已实测可靠）；
  禁止现有「新建独立任务复制分片 cutlist」路径作用于分片行（会散落孤儿）。
- 父级熔断：≥2 片同 error 签名失败 → 父行 failed＋告警人工介入，不再自动重试（防重试风暴）。

### 4.5 回调绑定（架构 P0，已部分先行）
- 分片回调绑定**必须**走 `map_cutlist_output_clip_ids`（按分片子 cutlist 起点匹配），禁用顺序兜底
  （分片 2 起必错绑候选 #0）。c6928c6 接线已恢复（b5a33a0），分片化把该函数从死代码变为唯一路径。

## 5. 派发与回滚（SRE M5/M6）

- **功能旋钮**：SystemConfig 运行时键 `slice_sharding_enabled`（默认 false），env 仅 bootstrap；只在创建任务时检查——关=不再产生新分片，在飞行照常收敛。管理端热翻，秒级 L1 回退。
- **两级回滚 runbook**：L1 关旋钮（秒级零风险）；L2 镜像回滚必须先排空（关旋钮→确认无 running 分片父行→回镜像，老 backend 无聚合回调，父行会永挂）。
- **deploy_phase2.sh 补自动 rollback tag**：G3 与 G4 之间 `docker tag <img> <img>:rollback-pre-<TS>`（F105 手工止血的动作固化）。
- 发布=backend+frontend+163 双 worker+beat **同批**（deploy_phase2 默认 SERVICES 全量）；112/Mac 节点无需升级（分片行对 worker 是普通任务）。

## 7. 监控（SRE 五指标全收，上线后看）

①分片健康率（failed>5% 或 sweep 命中>0 即查）；②拖尾系数 slowest/avg>1.5 收紧白名单；
③父行悬挂 >2h 人工介入（不等 7h sweep）；④闸门水位+429 率（防 M-闸门回归）；⑤112 iostat/网口（分片任务期 HDD %util>90 或千兆贴满→触发源片上限复核）。
