## 1. 背景与目标

163 数据中心自动化发布（Playwright Chromium + `set_input_files` 注入 + 数据中心 IP）多次被微信端**环境级风控**拦截（显式 `300001` 拒发，或"卡住"形态）。

**实证结论**（2026-08-18 对照实验）：本机 Edge + 真人 Finder 文件对话框上传成功 → **真实浏览器 + OS 文件对话框 + 真实 IP** 可过风控。

**目标**：搭建「163 编排 + 本机真实浏览器执行」的发布链路，让自动发布真正跑通。

## 3. 方案A 架构

```
┌─ 163（编排）─────────────────────────────────────────────┐
│  backend API：                                            │
│   • POST /api/publish/tasks  {executor:"local"}           │
│     → 不投递 celery，任务停在 pending 等本机执行器领取      │
│   • GET  /api/publish/tasks?executor=local&status=pending │
│   • GET  /api/slice-outputs/{output_id}                   │
│     → 返回 file_key + presigned_url（执行器免签下载）      │
│   • POST /api/publish/tasks/{id}/executor-result          │
│     → 执行器回传 processing/completed/failed              │
└───────────────────────────────────────────────────────────┘
            │  HTTP（内网 192.168.1.163:80）
┌─ 本机 Mac（执行）─────────────────────────────────────────┐
│  local-executor/executor.js（Node + Playwright）          │
│   轮询任务 → presigned 下载视频 → Playwright Chromium      │
│   headful 真实窗口 → 打开发布页（iframe）→ filechooser/    │
│   setInputFiles 上传 → 填标题/描述 → 点发表 → 回调 163      │
│   profile 持久化（~/.workbuddy/pw-publish-profile）        │
└───────────────────────────────────────────────────────────┘
```

**163 backend 改动（已部署）**：
- `publish_tasks.executor` 字段（`local`=本机执行器，不投递 celery）+ db_sync_columns/init.sql 兜底（163 手动 ALTER 补列）
- 回调接口 `POST /api/publish/tasks/{id}/executor-result`（仅 local 任务可回调，防误改远程任务）
- `GET /api/slice-outputs/{output_id}` 单查接口
- `GET /api/publish/tasks` 支持 `executor` 过滤

**本机执行器要点**：
- JWT：用 163 的 `JWT_SECRET`（HS256）本机生成，payload 需 `type=access` + `exp` + `iat`
- 下载：优先 presigned_url（免 MinIO 签名）
- 浏览器：**Playwright Chromium headful**（不用系统 Edge 第二实例，见踩坑）
- 上传：优先 file chooser（点击上传区）→ 兜底 iframe 内 `input[type=file]` setInputFiles

## 5. 关键踩坑记录

| 坑 | 现象 | 解决 |
|---|---|---|
| **视频号助手发布页是 iframe 结构** | 主 frame `platform/post/create` 是壳，内容（标题框/上传区/发表按钮）全在 iframe `micro/content/post/create`；主 frame 操作全扑空 | 所有表单操作必须走 iframe（`page.frames().find(url.includes('micro/content/post'))`） |
| **macOS 第二 Edge 实例连环崩** | 用户日常 Edge 占用 GPU → 第二实例 `GPU process isn't usable` trap 退出；`--start-minimized` 时 playwright click 派发失效（点击超时）；窗口模式偶发 502 | **弃用 Edge 第二实例，改 Playwright Chromium headful**（生命周期可控，不崩） |
| **playwright chromium 下载卡住** | 默认 CDN 无进展（只有 __dirlock） | `PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright` 镜像，29s 完成 |
| **发布页 file input 是隐藏的** | `input[type=file]`（ant-upload 隐藏 input）+ 可见 `.ant-upload-drag` 点击区 | playwright `setInputFiles` 对隐藏 input 也有效；点击区用 `.ant-upload-drag` |
| **JWT 401 "token 类型不正确"** | 只带 `sub` 不够 | payload 需 `type=access` + `exp` + `iat` |
| **worker 认领消息不处理**（mac-1） | 进程活、心跳 online、XREADGROUP 不拉任务 → pending 永久卡死 → 任务永远 running | 配套 **#255 worker 节点开关**：`PATCH /api/workers/{id}/enabled` 远程停用节点（Redis 控制 key + 心跳响应双源判定） |
