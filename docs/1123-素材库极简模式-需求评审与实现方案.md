# 素材库极简模式 · 需求评审与实现方案（2026-11-23）

## §0 这份文档解决什么

一线反馈素材库（① 导入 → ⑤ 成片墙）太繁琐，用户提了三条新需求，要求做成「极简模式（开关控制）」。本文＝五席评审结论 ＋ 拍板口径 ＋ 落地批次。**本文只定方案，不含代码。**

## §1 需求原文（用户原话，禁改写）

> 一、脚本生成：
> 1、钩子视频导入→选择分类→反推脚本→手动修改脚本→保存脚本
> 2、脚本文件上传→选择分类→手动修改脚本→保存脚本
> 3、个人可自定义脚本库，把想要的脚本添加到个人脚本库，并可打开脚本修改。
> 二、钩子视频生成：
> 1、勾选脚本（打开个人脚本库可一次多选）→上传三视图→豆包生成视频（生成数量可选）
> 三、拼接正片素材导出
> 1、选择豆包生成钩子视频（可多选）+正片（导入多个可多选）=一次组合生成多个投放素材。
> 2、角标、警示语、剧名、片尾引导可自选添加。(短剧切片模块中除选点外的那堆功能搬运)

## §2 用户拍板（2026-11-23 四问四答，全选推荐项）

## §3 现状操作量（评审实测，带证据）

- 反推按计时档位扣费：`backend/app/api/assets/misc.py:27`（11-23 拆包后 `assets.py` 只剩 38 行告警壳，**任何行号都要引 `assets/misc.py`**）（0.00054 元/秒，600 档 0.324 元/条）。
- 一线席补充：分类＝对 A–G 原型、改＝换皮填变量、保存＝抄成 20 行骨架提示词，**这三步他们本来就在手工做**（依据《钩子模版换皮参数设定.docx》与 `~/Downloads/视频号自动运营/常驻/豆包提示词方法论-真实感v2-20261111.md`）。所以极简模式的增值是「把抄表与扩写变成系统动作」，不是「发明新步骤」。

## §4 评审要点（已回读源码核实）

1. **需求一.2 后端已通九成。** `POST /assets/summaries/import-copy`（`assets/misc.py:1703`）＝"贴文案导入，跳过收链接→反推，建批次＋无视频文本壳素材＋候选进审核队列"；`POST /assets/import/paired` 的 `script_text`（`assets/misc.py:1851/:2136/:2146`）＝把脚本原文登记成一条 success 反推行。投产口对无反推稿的稿子有补稿路径（`assets/misc.py` produce 内 `script = await _prompt_script_of(db, asset)`）。**缺的只有两件事：这两个口都收不到 `category_id`（分类），以及脚本没有「存下来反复取用」的身份。**
2. **「个人脚本库」必须新表。** `asset_summaries.asset_id` 是 `NOT NULL + ondelete=CASCADE`（`backend/app/models/asset.py:427`），素材一删稿子即消失；且该表只有 `reviewed_by`、没有 `created_by`，「个人的」语义表达不出来。新表成本可控：`create_all` 自动建（`app/database.py:455`），幂等照 `AssetElementGuess` 的 `UniqueConstraint(body_hash, slot_key)` 抄，可见范围复用 `services/data_scope.py`。
3. **需求三 ≠ 今天刚上线的双批混拼。** 双批混拼（`backend/app/api/slice_helpers.py:208`，0072 迁移列）吃 AI 选点产物 `clip_candidates`；需求三输入是"已成片 × 已成片"，不涉及选点。可搬运的是切片侧叠加配置族（`slice.py:900-930`：`badges_config` 图片角标、`text_overlays_config` 固定文字角标＝警示语/剧名那类、`subtitle_config`、`*_mask`、`remotion_mix_config` 片头/转场/字幕/片尾；钩子拼接位 `slice.py:946/969` head/tail）。**但这套配置目前与切片任务生命周期绑死**（前端全内联在 `EpisodeDetail.tsx:1594-1650` 的 150+ 扁平字段里，角标上传挂 `/slice/badge-upload`），搬运需要一层与切片解耦的 overlay 参数结构。
4. **拼接实现已有三套**：`asset_compose_service.py`（两段直拼，`:12-16` 点名 `upload.py::_ffmpeg_concat` 硬编码 1920×1080）、`upload.py`、引擎侧 `engines/slice.py` 两处：通用 `concat_segments:983` 与封面内联 `concat=n=2`〔`:4198/:4210`〕〔11-23 复核订正：原写 `:4577` 落在 argparse 区，是错的〕。需求三再写一套就是第四套 → 方案里明确**收口成一套服务函数**。
5. **闸门现状（重要，别被"已自动化"误导）**：反推 409 闸仍在（`assets/misc.py:3867` ≥2 条必须 `confirmed=true`），但 11-12「钱面下架」（`a0d8a95`）后前端**恒发 `confirmed: true`**（`AssetListPanel.tsx:339/490/621`）；投板同理（`AssetProductionPanel.tsx:1075` 硬编码 true，`:409` 注释写明「按钮本身就是那一下人工确认」）。即现有保护是"一次点击/一批"，不是"逐条知情"。
6. **纠正两处席位误报**：① 产品席称"无母片文案入口不存在"→ 实际 `import-copy` 已存在；② 架构席称 `assets.py` 与 `misc.py` md5 相同 → 实测 **d1f35ae… vs 2e02568…，misc.py 多出 15 行**（今天 11-23 的入库归一化 720P@30），且 `importlib.util.find_spec('assets')` 实测 origin 指向 **未提交的包目录** `backend/app/api/assets/__init__.py → misc.py`。**新功能若写进 `assets.py` 就是死代码**（见 §6 待定①）。

## §5 落地方案

### 5.1 数据模型

- 新表 `asset_scripts`：`id / owner_id / name(≤60) / body(Text) / state('draft'|'ready') / category_id(FK asset_categories，可空) / source_kind('reverse'|'upload'|'manual') / origin_asset_id(FK SET NULL) / based_on_script_id(FK self) / body_hash / note / created_at / updated_at`。
  - 部分唯一索引 `(owner_id, body_hash)` 防重复存；`state` 两态即拍板①；`based_on_script_id` 让"库稿→可投稿"是派生而不是覆盖，出处链不断。
  - `origin_asset_id`/`based_on_script_id` 同时服务审计与"用别人的脚本投产"的责任归属（沿用 `ProduceRequest.cross_person_confirm` 口径）。
- `UserPreference` 加一列 `ui_config`（JSON）——**不复用 `slice_config`**（那是切片配置，语义会互相污染），端点照 `GET/PUT /slice/preferences`（`slice.py:468/482`）的形状新开 `GET/PUT /assets/ui/preferences`。默认值按角色：material/operator＝极简，admin＝全量。

### 5.2 三屏（极简视图）

1. **脚本屏**：导入钩子视频 →（选分类）→ 反推 → 改 → 存库｜脚本文件上传 →（选分类）→ 改 → 存库｜个人库列表（多选、就地改、定稿）。
2. **钩子视频屏**：多选脚本 → 三视图（复用 `AssetCardPicker`）→ 数量（**只映射板上 `total`**，`n` 保持默认；`assets/misc.py:453` 注释「混用会白烧 n×total」）→ 轻量过审那一下 → 投豆包（复用 produce＋dispatch）。
3. **组合导出屏**：多选钩子成片 × 多选正片 → 顺序（默认片头）→ 叠加预设（角标/警示语/剧名/片尾引导，默认"按剧/按原型一套预设、展开可微调"）→ 批量出包（复用现有交付包）。

### 5.3 批次（每批一个提交、独立过三道门）

| 批 | 内容 | 主要落点 | 规模 |
|---|---|---|---|
| S1 | 脚本库后端：`asset_scripts` 表＋读写口（读全员、写仅 owner、admin 改动进审计）＋`save-from-asset`（0 元收详规入库）＋`finalize`（库稿→可投稿，跑风险词重扫＋形态提示＋AuditLog）＋两个既有导入口补 `category_id` | `backend/app/api/assets/misc.py`、`models/asset.py`、`tests/` | ~700 行 |
| S2 | 极简视图屏 1＋2＋开关持久化（`ui_config`＋`GET/PUT /assets/ui/preferences`＋页顶切换）。**后端零新链路**：脚本→`import-copy` 等价服务函数→审核口→produce→dispatch | `frontend/src/pages/AssetLibrary.tsx` 挂新视图、`components/assets/simple/*` | ~1200 行 |
| S3 | 组合导出后端：`POST /assets/compose/matrix`（N 钩子 × M 正片，**单次 ≤20 条**，对齐 `ASSET_DISPATCH_MAX_PER_CALL`）；拼接 0 元；**校验必须排在投出之前**（现网教训：号池烧了才发现拼不了）；overlay 参数透传引擎子口；三套 concat 收口成一个服务函数；产物 `asset_outputs.kind='composed'` | `asset_compose_service.py`、`engines` 子口 | ~600 行 |

### 5.4 闸门复用清单（新端点一律不许自判）

风险词 block 重扫、审核硬拦、admin 豁免写审计、反推预算三档（confirmed/force）、RBAC `_PROD_ROLES`／`_REVIEW_ROLES`、钩子号"一发即烧"——全部在 service 层复用。极简模式**只折叠 UI，不旁路逻辑**。

### 5.5 明确不做

不加第四套 concat；不给 `wechat_dl_prompt_tasks` 加列（`models/asset.py:36` 明令禁止）；不动现有五环页签与教程组件（`StepGuide`/`PanelGuides`/`capture-guide-frames.mjs` 按页签文字点击，入口一旦隐藏即全红）；不新建旁路审核/成本端点；命名避开切片侧已有的 `fast 快速模式`。

## §6 开工前置（两条已定，只剩顺序）

1. **`backend/app/api/assets/` 包目录**：定＝**先单独收一个 commit**（含今天那 15 行入库归一化 720P@30；实测 `misc.py` ＝ `assets.py` ＋这 15 行、无其他差异，提交不丢东西），S1 起所有新端点写进 `misc.py`。⚠️ 本仓 11-23 有并行会话在进度/卡死工作流上活跃（见 `relay/1120-clip-workflow-slice` §2），这一刀要打得快、打前先看 `git status` 是否又冒出新的未提交改动。
